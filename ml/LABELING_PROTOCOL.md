# Протокол разметки smartphone RGB (target)

Версия: 2026-08-21. Это развёрнутая инструкция к пяти шагам на уже снятых
162 кадрах и к корпусу ~600 фото.

**Не размечайте все кадры рамками дефектов.** Три слоя обязательны, рамки —
только на части.

| Слой | На каких кадрах | Зачем |
|---|---|---|
| A. Каталог + `group_id` | все | sequence-safe split |
| B. Качество съёмки | все | quality gate |
| C. Рамки YOLO 4 классов | только заранее выбранные val/test (+ опционально малый train) | эталон |
| D. Без рамок | остальные | unlabeled target |

Адаптация стартует от замороженного YOLOv8s `student_best.pt`.

---

## Пункт 1. Сначала каталог, не рамки

### Зачем

Сеть запоминает не «файл», а **этот кусок металла**: чешую валика, ширину,
ржавчину пластины, как лежит блик. Если 8 ракурсов одного купона разрезать
случайно, шесть попадут в train, два в test. На test модель «узнает» тот же
шов, AP будет завышен, адаптация к смартфону не доказана. Поэтому единица
разбиения — физическое соединение, не jpg.

Рамки до каталога рисовать рано: вы начнёте с «самых красивых» кадров, они
же потом окажутся в test, и честный split уже не собрать.

### Что считать одним швом (`group_id`)

Один `group_id` = один физический объект съёмки:

- один купон / пластина / труба / тавр после одного прохода (или одной
  зачистки, если снимаете «до/после» как **один** объект);
- все расстояния 15–30 см, все углы, вспышка и без, резкость и смаз
  **этого** купона.

Разные `group_id`, даже если сварены тем же электродом в тот же день:

- другой стык на той же пластине, если это другой валик;
- повторный проход после полного переплава (новый валик);
- «тот же тип шва», но другая деталь.

Серые зоны (запишите в `capture.csv` и решите одинаково для всех):

- один стык, два кадра «со шлаком» и «после зачистки» — **один** group, если
  это тот же металл (иначе test увидит зачищенный шов, который модель уже
  видела в шлаке). Если хотите проверить именно «шлак vs чистый» как разные
  домены — тогда два group и в главе это отдельный фактор, не общий test.

### Имена файлов

```text
weld-017_s05.jpg
```

| Часть | Смысл | Пример ошибки |
|---|---|---|
| `weld-017` | физический шов, трёхзначный номер с 001 | `IMG_4521.jpg`, `21августа_3.jpg` |
| `s05` | кадр/ракурс этого шва | второй шов назван `weld-017_s09`, хотя это уже другой купон |

Не вшивайте в имя класс дефекта (`pore_03.jpg`): на кадре их может быть
несколько, и класс живёт в `.txt`, не в имени.

Сырьё не трогайте: копируйте `SvarshikProAI/target/raw/` → переименованные
файлы в `SvarshikProAI/target/images/`.

### Таблица `groups.csv`

Путь относительно файла манифеста. Для телефона `domain` всегда `target`.

```csv
image_path,group_id,domain,labeled
../target/images/weld-001_s01.jpg,weld-001,target,false
../target/images/weld-001_s02.jpg,weld-001,target,false
../target/images/weld-002_s01.jpg,weld-002,target,true
```

`labeled=true` только когда есть **экспертный** sidecar (в том числе пустой
`.txt` «дефектов нет»). Черновик YOLO без проверки — это `false`.

Команда `weldvision split` разносит **группы**: все строки с `weld-001`
уйдут целиком в train, val или test.

### Таблица съёмки `capture.csv`

Нужна главе «условия эксперимента», сеть её не читает.

```csv
image_path,group_id,date,phone,process,joint,slag_removed,distance_cm,intentional_bad,notes
../target/images/weld-001_s01.jpg,weld-001,2026-08-18,Pixel-7,RDS_MMA,butt,1,20,0,без вспышки
../target/images/weld-001_s08.jpg,weld-001,2026-08-18,Pixel-7,RDS_MMA,butt,1,40,1,намеренно далеко
```

`joint`: `butt` / `tee` / `lap` / `bead_on_plate`.  
Ограничение «только РДС» допустимо, его надо **написать** в постановке.

### Как разобрать уже лежащие 162 файла

1. Разложите превью по стопкам «это один купон».
2. Выдайте стопкам номера `weld-001` …
3. Внутри стопки пронумеруйте `s01`, `s02`, … в любом устойчивом порядке
   (например, сначала близко вдоль шва, потом далеко, потом брак съёмки).
4. Посчитайте **число стопок**, не число jpg. Дальше смотрите пункт 4:
   если стопок 6 — test из 1–2 швов бесполезен, нужны новые купоны.

## Пункт 2. Четыре класса LoHi, не ГОСТ

### Зачем английские id

Source LoHi размечен как `pore / deposit / discontinuity / stain`. Адаптация
отвечает на вопрос: «та же голова Detect на RGB телефоне». Если в target
появятся `undercut` и `slag`, вы сравниваете разные задачи и не имеете права
писать «AP как у LoHi».

В тексте диссертации можно писать «пора», в файлах — только:

```text
0 pore
1 deposit
2 discontinuity
3 stain
```

### Формат одной строки

```text
class_id center_x center_y width height
```

Все четыре числа — доли **этого** изображения, не пиксели и не мм.

Пример. Файл 4000×3000. Пора занимает пиксели `x1=1000, y1=800, x2=1200, y2=1000`:

```text
center_x = ((1000 + 1200) / 2) / 4000 = 0.275
center_y = ((800  + 1000) / 2) / 3000 = 0.300
width    = (1200 - 1000) / 4000      = 0.050
height   = (1000 - 800)  / 3000      = 0.067
```

Строка:

```text
0 0.275 0.300 0.050 0.067
```

Редактор (Label Studio / CVAT) считает это сам, если выбран экспорт YOLO.
Не пишите пиксели вручную.

Несколько объектов — несколько строк. Порядок строк не важен.

### Пустой `.txt`

Файл существует, внутри ничего (или только пустые строки) = на кропе нет ни
одного объекта четырёх классов. Это **негатив**, он учит сеть молчать.
Удалять пустой файл у `labeled=true` нельзя: загрузчик ждёт sidecar.

### Что обводить

**`pore` (0).** Тёмная ямка, пинхол, цепочка отдельных каверн на металле
валика. Каждая различимая пора — своя рамка. Две поры, которые слились в
одну полость, — один бокс. Не обводить:

- ложбинку между чешуйками;
- тень от бокового света;
- отверстие в шлаковой корке, если корка ещё не сбита (это не пора в металле;
  либо не размечать, либо `stain`, если это пятно шлака — см. ниже);
- всю осевую линию шва одним гигантским `pore`.

Рамка плотная, запас 2–5 пикселей, не «весь валик на всякий случай».

**`deposit` (1).** Брызги, наплыв, капли застывшего металла на пластине или
на валике, местное утолщение «горбом». Не обводить нормальную чешую РДС и
равномерный валик. Одна крупная капля — один бокс; россыпь мелких брызг —
либо по капле, либо группа, если они слиплись. Не клеить одну рамку на всю
пластину с десятью брызгами: AP тогда почти не штрафует пропуски внутри.

**`discontinuity` (2).** Видимый **разрыв непрерывности валика**: обрыв,
кратер в конце прохода, незаполненный участок, «провал» посередине.
Обводится только разрыв, не весь шов. Не обводить:

- линию стыка под валиком, если валик целый;
- границу сплавления как «дефект»;
- подрез по кромке (это **другой** ГОСТ-класс, в LoHi его нет — в
  `unmapped.csv`, не в `discontinuity`, пока эксперт не подписал иное).

**`stain` (3).** Локальное пятно на поверхности: остаток шлака, копоть,
масляное/ржавое пятно, которое не является самим валиком. Не обводить:

- радужную **побежалость** вдоль всего HAZ — на РДС она почти всегда;
- блик вспышки / окна;
- водяной знак стока, палец, линейку, наклейку.

Если побежалость пометить как `stain`, детектор будет срабатывать на каждом
кадре. В главе: «цвет побежалости не входит в stain».

### Чего камера не доказывает

Внутренний непровар, пористость в корне, шлак внутри шва. Не ставьте рамку
«потому что так бывает у РДС». Только то, что видно на этом RGB-кадре.

Неуверенный объект → нет рамки + строка в `unmapped.csv`:

```csv
image_path,reason,where
../target/images/weld-004_s03.jpg,possible_undercut,right_toe
../target/images/weld-009_s01.jpg,unclear_pit_vs_scale_shadow,mid_bead
```

### Какой файл размечать

Пайплайн на телефоне: полный кадр → ROI шва → плотный кроп → детектор.
Рамки ставятся на **тот jpg, который попадёт в `target/images`**.

Ориентир кропа: ширина валика примерно 1/5–1/3 кадра, шов примерно по
центру. Дальний кадр, где валик — нитка на фоне стола, для рамок не годится
(ему флаг `seam_too_small`, см. пункт 3).

Если храните и полный кадр, и кроп — в обучении только кроп, рамки только
на нём. Координаты полного кадра к кропу не переносятся автоматически.

## Пункт 3. Качество съёмки — на все 162 сразу

### Зачем отдельный слой

Гипотеза диссертации: плохой кадр не должен порождать уверенные
псевдорамки. Для этого нужен quality gate с экспертными метками
`acceptable / blur / underexposed / overexposed / glare / seam_too_small`.
Эвристика «яркость + лапласиан» годится только как заглушка.

Это **не** классы дефектов. Кадр может быть `acceptable=1` и при этом без
пор, или `blur=1` при хорошо видимом наплыве.

### Файл `quality.csv`

Мультилейбл: несколько единиц в одной строке норма.

```csv
image_path,acceptable,blur,underexposed,overexposed,glare,seam_too_small
../target/images/weld-001_s01.jpg,1,0,0,0,0,0
../target/images/weld-001_s08.jpg,0,1,0,0,1,0
../target/images/weld-002_s04.jpg,0,0,0,0,0,1
```

### Как ставить каждый флаг

**`acceptable`.** `1`, если по этому кадру сварщик/эксперт *в принципе*
может судить о поверхностных дефектах валика: шов читается, нет сильного
смаза, экспозиция не убита, блик не залил ось шва, валик достаточно крупный.
Иначе `0`. Не ставьте `acceptable=1` «потому что дефект где-то угадывается».

**`blur`.** Смаз или мимо фокуса: чешуя мыльная, поры нельзя отделить от
шума. Лёгкая шероховатость JPEG — не blur.

**`underexposed`.** Валик в провале, детали только после сильного осветления.
Тёмная пластина при нормально освещённом шве — не underexposed.

**`overexposed`.** Выбитые белые поля, где должен быть металл. Блик локальный
— скорее `glare`, не обязательно overexposed на весь кадр.

**`glare`.** Зеркальный блик (окно, лампа, вспышка) закрывает часть валика
или имитирует пятно. Снимайте без вспышки; оставшиеся блики как раз учат
gate.

**`seam_too_small`.** Валик занимает ничтожную долю кадра (далеко / широкий
угол). Даже если резкий и светлый — для детектора пор это почти бесполезно.

Намеренно плохие кадры из плана съёмки здесь обязательны. Без них gate
увидит только «всё хорошее» и на смазе в поле начнёт врать.

Размечайте quality **на всех 162 до рамок**: это быстро (несколько секунд на
кадр) и не зависит от заморозки val/test.

## Пункт 4. Рамки только на заранее выбранных швах val и test

### Зачем не размечать все 600

Адаптация в коде — teacher строит псевдоразметку на **unlabeled** RGB.
Если все кадры уже с эталоном, вы просто дообучите детектор с учителем и
не проверите гипотезу quality-aware pseudo-labels.

Эталон нужен, чтобы:

- на val подобрать порог и не переобучить адаптацию;
- на test один раз измерить AP/recall на телефоне;
- опционально дать fully-supervised верхнюю границу на 1–2 швах.

### Делить швы, не файлы

600 фото ≈ 40–80 `group_id`, если по 8–15 кадров на шов. Целевые доли
**по числу швов**:

| Роль | Доля швов | Рамки | Манифест после `weldvision split` |
|---|---|---|---|
| unlabeled | ~60% | нет | `target_unlabeled.txt` |
| val | ~20% | экспертные | `target_val.txt` |
| test | ~20% | экспертные | `target_test.txt` |

Test замораживается **до** подбора порога 0.25, температуры и силы quality.
На val можно смотреть. Test — в конце, один прогон в главу.

В test и val должны попасть по возможности:

- стык / тавр / нахлёст / валик на пластине;
- со шлаком и без;
- хотя бы несколько пор, наплывов, разрывов, пятен;
- 2–3 намеренно плохих кадра (для оценки gate, не для AP дефектов).

Не кладите в test только «идеальные» макро.

### Что делать на текущих 162

Сначала число стопок из пункта 1.

**Если швов ≥ 15.** Можно наметить test ~3–4 шва и val ~3 шва уже сейчас,
разметить их рамками, остальное unlabeled. При досъёмке новые купоны
добавляйте в основном в unlabeled и добивайте test до ≥ 15 швов / ≥ 80
кадров с эталоном.

**Если швов 8–14.** Val/test наметьте, но test пока тонкий. Доснимайте
**новые купоны**, не 20-й ракурс тех же восьми. Рамки на «красивых» кадрах
train не рисуйте.

**Если швов ≤ 7.** Рамки почти не начинайте: любой test будет из 1–2 деталей.
Каталог + quality — да. Съёмка — приоритет.

Не перекидывайте шов из test в train, «потому что на нём лучше поры». Это
подгонка теста.

### Опциональный размеченный train

1–2 шва с полными рамками, которые **не** входят в val/test, для эксперимента
«верхняя граница: учим student ещё и на экспертном RGB». Это отдельный
прогон, не смешивать с основным unlabeled-сценарием в одной таблице.

### После каталога

```bash
weldvision split --manifest data/manifests/groups.csv --output data/manifests --seed 42
weldvision audit --manifest data/manifests/groups.csv --seed 42
```

Audit обязан пройти: один `group_id` не встречается в двух split, нет
побитовых дубликатов jpg между split.

## Пункт 5. Чем рисовать и можно ли звать YOLO

### Инструмент

Нужен экспорт **YOLO detect** (прямоугольники, не полигоны, не сегментация):

- Label Studio локально;
- CVAT;
- Roboflow — только если итоговые `.jpg` + `.txt` остаются у вас и классы
  0–3 совпадают.

Полигоны не рисуйте: детектор считает xyxy. Конвертация «полигон → bbox»
добавляет ошибки по краю.

Структура на диске:

```text
ml/data/target/
├── classes.txt
├── images/weld-017_s05.jpg
└── labels/weld-017_s05.txt
```

`classes.txt`:

```text
pore
deposit
discontinuity
stain
```

Код ищет `labels/имя.txt`, `labels/имя.yolo` или sidecar рядом с картинкой.

### Label Studio, минимальный контур

1. Ставьте локально (Docker или `pip install label-studio`).
2. Тип проекта: Object Detection with Bounding Boxes.
3. Labels: `pore`, `deposit`, `discontinuity`, `stain` в **этом** порядке
   (порядок = id 0..3 при экспорте YOLO).
4. Импорт только тех jpg, которые по пункту 4 идут в val/test.
5. Горячие клавиши на 4 класса, зум на поры.
6. Экспорт YOLO, проверка: число `.txt` = число картинок, пустые файлы на
   месте, ни одной координаты вне `[0, 1]`, ни одного class_id ≥ 4.

### Черновик от YOLOv8s

Можно: прогнать `student_best.pt`, импортировать рамки как pre-labels,
пройтись глазами.

Нельзя: скопировать сырой вывод в `labels/` и назвать эталоном. На RGB
телефон даст ложные рамки на чешуе, блике и побежалости. Тогда AP на test
измерит согласие сети с собой, а не качество адаптации.

Правило приёмки черновика: каждая рамка либо исправляется, либо удаляется;
пропущенные поры добавляются вручную; кадры без дефектов остаются пустым
`.txt`, даже если YOLO что-то нашёл.

Порог черновика лучше низкий (например 0.15–0.25), чтобы эксперт видел
кандидатов, а не только «уверенный мусор».

### Согласованность

Один разметчик для магистратуры нормален. Зафиксируйте дату этой версии
протокола. Через 1–2 недели разметьте заново 40–50 val-кадров вслепую:
совпадение = тот же класс и IoU ≥ 0.5. Долю совпадения внесите в главу.
Второй человек — сначала 20 кадров сверки протокола, не «усреднение» боксов.

## Чего не делать (короткий список)

- split по файлам или «каждый 5-й в test»;
- один купон в train и test;
- классификация кадра «брак / норма» вместо рамок;
- рамка на весь шов как `discontinuity`;
- побежалость = `stain`;
- водяной знак, палец, линейка как дефект;
- рентген и макрошлиф в тот же target;
- правка рамок после того, как посмотрели test-метрику;
- новые классы «подрез», «шлак», «трещина» в тех же `.txt`.

## Порядок на этой неделе (162 кадра)

1. Сырьё в `SvarshikProAI/target/raw/`.
2. Стопки купонов → `weld-XXX_sYY.jpg` → `groups.csv` + `capture.csv`.
3. `quality.csv` на все 162.
4. По числу швов решить, можно ли уже заморозить val/test (пункт 4).
5. Рамки только на этих швах, 4 класса, YOLO `.txt`.
6. Остальное — unlabeled.
7. Досъёмка до 600: новые швы, баланс типов стыка, шлак/без, 15–20
   намеренно плохих кадров, примеры всех четырёх классов.

## Абзац в диссертацию

Разметка target — экспертные прямоугольники таксономии LoHi-WELD на видимой
поверхности РДС-швов со смартфона; кадры группируются по физическому
соединению; качество съёмки размечается отдельно; часть корпуса без рамок
для quality-aware adaptation. Полный ряд ГОСТ-дефектов этим детектором не
заявляется.
