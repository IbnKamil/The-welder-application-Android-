# Что делать с фото швов (вид сверху)

Версия: 2026-08-21. Модель и приложение рассчитаны **только** на съёмку сверху:
ширина валика ≈ **1/5…1/3 ширины кадра**. Другие ракурсы не снимайте и не
размечайте.

Ниже — порядок действий руками. Теория split/LoHi нужна только там, где без
неё можно испортить датасет.

## Итог: какие файлы у вас должны появиться

```text
SvarshikProAI/target/
  raw/                 оригиналы с телефона, не трогать
  images/              weld-001.jpg, weld-002.jpg, …
  labels/              weld-017.txt  — только у кадров с эталоном
  groups.csv
  quality.csv
  capture.csv          по желанию, для главы
  unmapped.csv         если объект не из 4 классов
```

Рамки рисуете **не на всех** 162 и не на всех 600.

---

## Шаг 0. Папки на диске

1. На Google Drive создайте `SvarshikProAI/target/raw/` и `SvarshikProAI/target/images/`.
2. Скопируйте все 162 фото в `raw/`. Оттуда больше ничего не удаляйте.
3. В `images/` будут **копии** с нормальными именами.

Каждое фото уже должно быть сверху, валик по центру, ширина валика примерно
1/5–1/3 кадра. Если кадр снят сбоку или валик — тонкая нитка — не кладите его
в `images/` как рабочий; пометьте в `quality.csv` (шаг 3) как плохой.

---

## Шаг 1. Дать каждому фото имя шва

Откройте превью и решите: **это тот же кусок металла, что уже был, или новый?**

- Новый купон / новый стык / новый валик → следующий номер.
- Тот же купон, ещё один кадр сверху (пересняли, чуть ближе) → **тот же номер**,
  добавьте суффикс кадра.

Имена:

```text
один кадр на шов:     weld-001.jpg
несколько кадров:     weld-001_s01.jpg
                      weld-001_s02.jpg
```

Номер `001`, `002`, … — это физическая деталь. Не `IMG_4588.jpg`.

Практично: в проводнике/Drive включите крупные превью и раскладывайте в
виртуальные группы. Потом переименуйте пачкой.

Если почти все 162 — **разные** швы по одному кадру, будет `weld-001.jpg` …
`weld-162.jpg`. Так даже лучше для test.

---

## Шаг 2. Таблица `groups.csv`

Создайте таблицу (Google Таблица → Файл → Скачать → CSV) с четырьмя колонками:

```text
image_path,group_id,domain,labeled
```

По одной строке на каждый файл в `images/`.

Пример, три разных шва по одному кадру:

```csv
image_path,group_id,domain,labeled
../target/images/weld-001.jpg,weld-001,target,false
../target/images/weld-002.jpg,weld-002,target,false
../target/images/weld-003.jpg,weld-003,target,false
```

Пример, два кадра одного шва:

```csv
../target/images/weld-010_s01.jpg,weld-010,target,false
../target/images/weld-010_s02.jpg,weld-010,target,false
```

Правила, которые нельзя нарушить:

- `domain` везде `target`;
- `group_id` одинаковый у всех кадров **одной детали**;
- пока рамок нет, везде `labeled` = `false`. Когда нарисуете эталон (шаг 5),
  у этих строк поставьте `true`.

На этом шаге **рамки ещё не рисуете**.

---

## Шаг 3. Таблица `quality.csv` — все 162 кадра

Вторая таблица, тоже CSV. Колонки:

```text
image_path,acceptable,blur,underexposed,overexposed,glare,seam_too_small
```

На каждый кадр поставьте `0` или `1`. Можно несколько единиц в одной строке.

Что ставить, глядя на фото:

| Колонка | Ставьте `1`, если |
|---|---|
| `acceptable` | сверху, валик читается, ширина примерно 1/5…1/3, по фото можно судить о поверхности |
| `blur` | смазано / мимо фокуса, чешуя мыльная |
| `underexposed` | шов в провале, деталей не видно |
| `overexposed` | металл выбит в белое |
| `glare` | блик закрыл валик |
| `seam_too_small` | валик уже, чем ~1/5 кадра, или снят издалека |

`acceptable=1` только если кадр годится как **тот вид, для которого будет
инструкция в приложении**. Сняли сбоку — `acceptable=0`.

Пример:

```csv
image_path,acceptable,blur,underexposed,overexposed,glare,seam_too_small
../target/images/weld-001.jpg,1,0,0,0,0,0
../target/images/weld-002.jpg,0,1,0,0,0,0
../target/images/weld-003.jpg,0,0,0,0,0,1
```

Это ещё не рамки дефектов. Проставьте на все 162, это быстро.

---

## Шаг 4. Решить, какие швы размечать рамками

Не обводите все фото.

1. Откройте `groups.csv` и список уникальных `group_id` (уникальные швы).
2. Выпишите номера на бумагу.
3. Отложите **примерно пятую часть швов** в кучку «TEST» и ещё **примерно
   пятую** в «VAL». Остальные — «без рамок».
4. Больше не перекладывайте шов из TEST в другую кучку.

Если сейчас ~162 **разных** шва: в TEST ≈ 30 номеров, в VAL ≈ 30, остальные
~100 без рамок. Если швов мало (например 20 деталей по несколько кадров) —
в TEST положите 4–5 деталей целиком (все кадры этой детали), не отдельные jpg.

Рамки будете рисовать **только** на фото из кучек VAL и TEST.

---

## Шаг 5. Нарисовать прямоугольники (только VAL и TEST)

### Куда класть файлы

```text
images/weld-017.jpg
labels/weld-017.txt
```

Имена без расширения совпадают.

### Какая программа

Поставьте [Label Studio](https://labelstud.io/) (или CVAT). Создайте проект
**Object Detection → Bounding Boxes**. Четыре подписи **в таком порядке**:

```text
pore
deposit
discontinuity
stain
```

Импортируйте **только** jpg из VAL и TEST, не все 162.

Экспорт: YOLO. Должны получиться `.txt` с числами от 0 до 1.

### Что обводить на кадре сверху

Четыре кнопки — четыре типа объектов. На одном фото может быть 0, 1 или
много рамок.

1. **pore** — тёмная ямка (пора) на валике. Каждая ямка — свой прямоугольник.
   Не обводите бороздку между чешуйками и не обводите весь шов.
2. **deposit** — брызги металла, наплыв, капля рядом с валиком. Не обводите
   обычную чешую «ёлочкой».
3. **discontinuity** — дырка/обрыв валика, кратер, кусок шва не заполнен.
   Обведите только разрыв, не весь валик от края до края.
4. **stain** — локальное пятно грязи/шлака на поверхности. Не обводите
   радужный цвет побежалости вдоль шва (он почти на каждом РДС-кадре).

Не уверены, что это за объект — **не рисуйте** рамку. Запишите имя файла в
`unmapped.csv`.

Дефектов этих четырёх видов нет → сохраните **пустой** `weld-017.txt`
(файл есть, внутри пусто). Так вы помечаете «чистый шов».

Подрез, непровар внутри, шлак в корне **не** рисуйте: камера сверху этого не
доказывает, отдельных классов под них в модели нет.

После экспорта у каждой строки VAL/TEST в `groups.csv` поставьте `labeled,true`.

---

## Шаг 6. Остальные фото

Все `group_id`, которые не в VAL и не в TEST:

- лежат в `images/`;
- есть строка в `groups.csv` с `labeled,false`;
- **нет** эталонного `.txt` (или он не считается эталоном);
- для обучения адаптации этого достаточно.

Их не нужно обводить «чтобы было».

---

## Шаг 7. Доснять до ~600

Снимайте так, как будет написано в приложении: **строго сверху**, валик
1/5…1/3 ширины кадра, без вспышки, основная камера.

Нужны новые **детали** (новые `weld-XXX`), не сотни повторов одного купона.
Среди новых: стык, тавр, нахлёст, валик на пластине; со шлаком и после
зачистки; кадры с порами/наплывом/обрывом/пятном; плюс штук 15 намеренно
плохих (смаз, далеко, блик) — они идут в `quality.csv`, не обязательно в рамки.

Новые швы в основном добавляйте в «без рамок». Кучки VAL/TEST дополняйте,
пока в TEST не наберётся примерно ≥ 80 кадров **и** достаточно разных деталей.

---

## Чего не делать

- Снимать сбоку / под 45° «для разнообразия» — этой модели такого вида не будет.
- Обводить все 162 «на всякий случай».
- Называть классы в файлах по ГОСТ (`подрез`, `шлак`) — в `.txt` только
  `pore/deposit/discontinuity/stain`.
- Кладть один и тот же `weld-010` и в TEST, и в «без рамок» как разные задачи:
  все кадры `weld-010` живут вместе.
- Копировать сырые рамки YOLOv8s в `labels/` без проверки глазами.

Когда `groups.csv` заполнен:

```bash
weldvision split --manifest data/manifests/groups.csv --output data/manifests --seed 42
weldvision audit --manifest data/manifests/groups.csv --seed 42
```
